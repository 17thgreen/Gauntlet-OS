# Failure Cemetery

Retain every rejected strategy/idea and relevant failed, invalid, blocked, inconclusive or retired experiment. These categories are distinct; do not call an unmeasurable hypothesis disproven.

Each entry uses a [Failure Record](../schemas/FAILURE_RECORD.md) and links the original idea, family, frozen parameters, actual results, conditions, proposer, Red Team findings and decision.

The Archivist maintains indexes by mechanism/family, data dependency, domain, failure cause, date and candidate lineage. The Conductor checks these indexes before new commissions.

A proposal resembling a failed family must cite it and explain its material novelty: new data, corrected implementation, a different mechanism, changed conditions or a registered falsification of the earlier failure explanation. Renaming a formula is not novelty.

Reopening creates a new linked version and explicit Decision Record. Preserve the old failure and consumed holdouts. Reuse lessons and approved tooling; do not reuse a failed evaluation as untouched evidence.

Failure memory is an input to future work, not a graveyard hidden from the active queue.
