# Discovery funnel

**Status:** RATIFIED as workflow (not a new constitutional tier)  
**Runs beside:** any live Experiment pack (today: ALMANAC, crypto-alpha)  
**Ancestor:** TORII — ChatGPT reverse-engineered a working desk, then the prompt was *do not copy it; reverse-engineer the best object*.

## Why this file exists

Discover → Experiment → Operate is already law. Ideas were still landing on [FUTURE_IDEAS](../records/FUTURE_IDEAS.md) as if listing them were validation.

Split the board:

| Board | What it is |
|-------|------------|
| `records/inbox/` | Raw tickets. Unsure is the point. |
| Discovery run | Challenge / Scout / cheap test. Separate Bot group from the live Experiment Conductor. |
| `records/FUTURE_IDEAS.md` + VC `REGISTRY.md` | **Survivors only.** |
| Domain pack + Experiment Commission | After KEEP, if Governor wants a lab. |

ALMANAC does not pause because a clip-desk ticket arrived. Two groups, one OS.

## Funnel

```
IDEA_IN          records/inbox/IDEA-YYYYMMDD-slug.md
    |
    | Governor or Discovery clerk: one-line object + copy ban
    v
CHALLENGE        protocols/CHALLENGE.md (or Scout Field Report if the job is street-scan only)
    |
    v
AUDITOR          ADMIT / RETURN / BAN   (specified enough? permitted?)
    |
    v
CHEAP TEST       smallest credible observation — not the product
    |
    v
VERDICT          KILL | PIVOT | KEEP
    |
    +-- KILL     Failure Record; leave inbox stamped; do not promote to FUTURE_IDEAS
    +-- PIVOT    New IDEA ticket with the *new* object sentence; old ticket SUPERSEDED
    +-- KEEP     Row on FUTURE_IDEAS and/or VC REGISTRY. Still authority = NONE.
                 Experiment pack only by a separate Decision Record.
```

Partial accept **is** PIVOT. Example: “clip farm other people’s YouTube” → “Clip Desk for footage we own or license.” The stolen-content object is dead; the owned-footage object is a new ticket.

## Parallelism

| Group | Defends |
|-------|--------|
| Experiment Conductor (ALMANAC, crypto, …) | The live commission |
| Discovery clerk / Challenger / Scout | The inbox |

The Experiment Conductor does not schedule Discovery on a mission it is defending. Discovery does not write READY cards for the live pack.

Cap concurrent Discovery tickets in run-config (suggested: 1 cheap test at a time until a clerk exists). Inbox can hold many; only one is IN_FLIGHT.

## TORII rule (the single-shot that mattered)

1. Name a **working machine** (friend’s desk, Huang & Fan, Opus-style clipper, RohOnChain post).
2. **Copy ban.**
3. Attack the object; return models A/B/C and a smallest credible test.
4. Unobserved numbers stay labeled. “1M views = $2k” is `[E]` until someone’s account page shows it.

A pretty memo is not KEEP.

## What KEEP buys

- A row on the survivor index
- Permission to write an Experiment Commission draft
- Not Operate, not spend, not a second lab by default

## What BAN / KILL buys

- Cemetery memory so the same object cannot re-enter as a rename
- PIVOT must cite the killed object and the new sentence
