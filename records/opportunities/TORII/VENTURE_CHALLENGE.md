## Ambition (preserve this)

Do not agree with the playbook because it is in the repo. Identify weaknesses, hidden objects, logistics/regulatory bottlenecks, and superior models. Optimize for **risk-adjusted return on deployed capital**, not shelf photos.

The flywheel in the source prompt still stands as a *target*, not a claim: demand intelligence → supplier intelligence → buyer → preorder → procure → fulfill → transaction data → better demand. You may replace any node.

You may conclude the best company is a distributor, a marketplace, sourcing-as-a-service, a data desk, or a combination. You may conclude inventory should stay near zero. You may conclude the idea should remain parked.

## Standing objectives

- Fastest credible path to the first *collected* dollar
- Strong net after all costs, including human minutes
- Simple delivery that actually ships
- Sustainable automation with an **absolute hours cap**
- Repeat orders if the first dollar is real

When those fight each other, show the tradeoff. Do not hide it in a score. Authenticity/IP is a **hard gate**, not 5% of a weighted score.

## Anti-theater (non-negotiable)

- Every commercial number: observed / calculated / assumed / unknown, with provenance.
- Every capability: Working / Simulated / Blocked / Unbuilt.
- One complete workflow before architecture diagrams: real input → persisted decision → approval → verifiable output.
- Empty book: no invented buyers, quotes, POs, or revenue. DEMO data labeled DEMO.
- Failures recoverable: missing comps, dead supplier, failed freight API, duplicate SKU.
- Human minutes per quote, per PO, per exception. “95% automated” without minutes is incomplete.
- No $25M–$500M chapter until the first-dollar test is specified. Expansion path ≠ forecast.

## Required attack list

1. Five weaknesses in the playbook.
2. Five missed objects (not five features on the same gateway).
3. Three models that could beat demand-first wholesale, including one that does not own inventory.
4. What is actually defensible (data, allocation, trust) vs what is a slogan.
5. Capital-efficient version vs inventory-led version — which gets first dollar sooner.
6. What must stay human at v0; what can be code immediately.
7. Assumptions in the playbook and in the friend’s economics that are probably wrong.
8. Fastest path to first collected dollar (not first $1M).
9. Legal/platform/customs/authenticity risks that kill a SKU before margin math.
10. Build specification an engineering agent can start **without** inventing a live store.

## Required deliverable shape

- One-page verdict: KEEP playbook / PIVOT object / KILL TORII
- Redesign (if not KILL) covering customer, offer, source, cash, delivery
- First experiment with baseline, green, kill, stop
- Build spec: files, data stores, human gates, empty states, done-condition
- Layman brief
